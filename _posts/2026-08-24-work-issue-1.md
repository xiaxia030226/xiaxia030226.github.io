在鸿蒙（HarmonyOS）手机的微信小游戏（WebGL）上，触摸事件由 JS 桥异步转发到 Unity，与标准 Android/iOS 存在差异，导致原有的触摸判断逻辑在鸿蒙上出现点击失效、拖动失效。

## 旧判断逻辑

之前按下、抬起、双指打断、取坐标都直接依赖 `Input.touchCount` 和 `Input.GetTouch(0)`：

```c#
// 按下判定
if (Input.touchCount == 1 && Input.GetTouch(0).phase == TouchPhase.Began)
{
    // 按下成功
}

// 抬起判定
if (Input.touchCount == 1 && Input.GetTouch(0).phase == TouchPhase.Ended)
{
    // 抬起
}

// 双指打断判定
if (Input.touchCount >= 2)
{
    // 退出单指拖动/特效
}

// 取坐标
Vector3 pos = Input.GetTouch(0).position;
```

这套逻辑在 Android 和 iOS 上都正常，但在鸿蒙平台上会失效。原因是鸿蒙触摸事件经过 JS 桥异步转发，`Input` 数组的行为与原生平台不一致，具体表现为下面四个问题。

## 鸿蒙平台的四个问题

### 1. 幽灵触点：Ended/Canceled 的触点不会立刻移除

已经 `Ended` 或 `Canceled` 的触点不会立刻从 `Input` 数组中移除，导致 `Input.touchCount == 1` 判断单指失效，`Input.GetTouch(0)` 取操作手指也失效。

**解决方案**：引入主手指逻辑，记录主手指 `fingerId`，遍历 `Input.touches` 数组来维护。

```c#
private int _primaryFingerId = -1;

void UpdatePrimaryTouch()
{
    foreach (Touch touch in Input.touches)
    {
        // 首个按下的触点记录为主手指
        if (_primaryFingerId == -1 && touch.phase == TouchPhase.Began)
        {
            _primaryFingerId = touch.fingerId;
        }

        // 主手指抬起/取消，释放身份
        if (touch.fingerId == _primaryFingerId &&
            (touch.phase == TouchPhase.Ended || touch.phase == TouchPhase.Canceled))
        {
            _primaryFingerId = -1;
        }
    }
}
```

关于"幽灵触点何时从 `Input` 数组删除"，答案是：**不知道，也无法知道**。没有任何 API、事件或文档说明它何时被清理，实测表现就是"使用期间 `touchCount` 常年 >1"。

能确认的只有一点：**清理只会迟到，不会提前**——桥不会在任何真实手指还按着的时候把数组清空。所以 `touchCount == 0` 可以作为"全部真实手指都抬起"的信号，但它"什么时候清"是完全不可预测的。

### 2. 单帧丢帧/合帧：某一帧 Input.touches 整包缺失

JS 桥异步转发时，某一帧 `Input.touches` 可能整包缺失。此时数组里只剩幽灵触点，主手指的输入缺失，不能立刻判定手指抬起。

**解决方案**：失联宽限，连续 2 帧都没出现主手指的输入才释放主手指身份，当前帧继续使用上一帧缓存的位置。

```c#
// 失联宽限：容忍 JS 桥单帧丢帧/合帧，连续 2 帧未出现才释放身份
_primaryMissingFrames++;
if (_primaryMissingFrames >= 2)
{
    _primaryFingerId = -1;
    _primaryMissingFrames = 0;
}
```

### 3. fingerId 漂移：同一根手指跨帧 fingerId 变化

同一根物理手指，跨帧后 `fingerId` 可能发生变化。配合失联宽限，释放身份后重新寻找主手指，判断依据是 `touch.phase == TouchPhase.Moved`。

```c#
if (_primaryFingerId == -1)
{
    foreach (Touch touch in Input.touches)
    {
        if (touch.phase == TouchPhase.Moved)
        {
            _primaryFingerId = touch.fingerId;
            break;
        }
    }
}
```

### 4. mousePosition 不跟随触摸

触摸时 `Input.mousePosition` 不会更新，所以遮挡检测、坐标取值都不能用鼠标兜底。但注意：华为折叠屏、平板、手写笔会产生鼠标输入，此时 `mousePosition` 是有效的。

**解决方案**：坐标统一从主手指取。

```c#
public static Vector3 GetPointerPosition()
{
#if UNITY_EDITOR
    return Input.mousePosition;
#else
    // 优先返回主手指坐标（规避鸿蒙触摸事件异步转发导致 GetTouch(0) 不稳定的问题）
    if (TryGetPrimaryTouch(out Touch t))
    {
        return t.position;
    }
    return Input.mousePosition;
#endif
}
```

## 总结

| 问题 | 表现 | 应对 |
|---|---|---|
| 幽灵触点 | Ended/Canceled 触点不立即移除，touchCount 常年 >1 | 主手指 fingerId 逻辑，不依赖 touchCount |
| 单帧丢帧 | 某帧 touches 整包缺失 | 失联宽限 2 帧 |
| fingerId 漂移 | 同一手指跨帧 id 变化 | 释放后按 Moved 重新识别 |
| mousePosition 不跟随 | 触摸时不更新 | 坐标统一取主手指 position |

**鸿蒙上不要信任 `touchCount` 和 `GetTouch(0)`，用主手指 `fingerId` 来跟踪真实操作的手指**。
