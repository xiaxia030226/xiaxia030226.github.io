枪械系统做完后试玩，发现鼠标完全失灵：点左键不发射，转向也没反应，但键盘（移动、切枪）全部正常。最后定位到编辑器的一个触摸模拟选项把 Mouse 设备禁用了。本篇记录排查过程和修复方法。

## 症状

- 键盘输入正常：WASD 移动、数字键切枪都好使
- 鼠标输入全灭：位置冻结（转向失效），左键点击无效
- Console 没有任何报错，配置资产、子弹预制体、装配代码静态检查全部正常

## 排查过程

### 第一层：给攻击链路埋探针

在三个关键环节各加一条临时日志：玩家检测到输入、武器系统校验状态、子弹真正发射。跑起来点击左键，一条日志都没有——说明输入根本没到达代码。

### 第二层：探针升级，直读设备原始状态

把探针改成不依赖按键触发，每秒无条件输出一次鼠标设备的原始状态：

```csharp
var mouse = UnityEngine.InputSystem.Mouse.current;
Debug.Log(mouse == null
    ? "鼠标设备不存在"
    : $"enabled={mouse.enabled}, pos={mouse.position.ReadValue()}, left={mouse.leftButton.isPressed}");
```

结果是设备存在，但 pos 永远 (0,0)、left 永远 False——从 Play 开始鼠标一个事件都没进来过。设备在、驱动通、但事件为零，问题在设备层，不在动作绑定。

### 第三层：Input Debugger 看设备真相

Window → Analysis → Input Debugger，左侧设备树双击 Mouse，顶部黄色横幅直接给出答案：

> Device is DISABLED. Control values will not receive updates.

Flags 里带着 `DisabledInFrontend` 和 `DisabledInRuntime`。按提示右键 Enable Device 后又被禁用回去——有东西在主动、持续地禁用鼠标。

## 根因

罪魁祸首是 Input Debugger → Options 里的 **Simulate Touch Input From Mouse or Pen**（触摸模拟）。它启用时会禁用 Mouse 设备，把鼠标事件翻译成触摸事件——本来是给触屏游戏在编辑器里模拟手指用的。

这个选项最坑的地方在于持久化机制：

- 选项状态保存在编辑器级偏好里，不在项目文件中，项目里找不到任何痕迹
- 同一编辑器版本的所有项目共享这个偏好
- 只要被开启过一次，之后每次启动 Unity 都会自动恢复，表象是"从没开过却每次都自动打开"

Unity 官方论坛上有相同案例：有人只是试了一下这个选项，鼠标输入就持续失效了。

## 修复

### 界面根治

Input Debugger → Options → 取消勾选 Simulate Touch Input From Mouse or Pen。取消动作会把持久化状态写回关闭，一次即断根。

### 代码兜底

在 GameInput.Init 末尾加防御代码，每次启动自动关闭触摸模拟并确保鼠标启用，即使选项再被误开游戏也能自愈：

```csharp
// 防御：编辑器中开启"触摸模拟"会禁用 Mouse 设备，
// 导致游戏里鼠标位置和按键全部失效。
if (UnityEngine.InputSystem.EnhancedTouch.TouchSimulation.instance != null)
{
    UnityEngine.InputSystem.EnhancedTouch.TouchSimulation.Disable();
}
if (Mouse.current != null && !Mouse.current.enabled)
{
    InputSystem.EnableDevice(Mouse.current);
}
```

## 排查收获

- 某一类设备整体失灵、其他设备正常，先用 Input Debugger 查设备启用状态，确认事件有没有到达输入系统
- 某个设置"每次都自动恢复"，考虑编辑器级偏好持久化（EditorPrefs/注册表，跨项目共享），别只在项目文件里找原因
