ECS 架构的核心思想很直接——**数据跟逻辑分开**。实体只是 ID，组件是纯数据，系统负责逻辑。今天先梳理最底层的两个文件：Entity 标识和 ComponentTypes 组件定义，后续所有系统都建立在它们之上。

## Entity.cs — 实体标识

```csharp
using System;

/// <summary>
/// 实体标识（轻量，仅含 ID + 版本号防止悬垂引用）
/// </summary>
public struct Entity : IEquatable<Entity>
{
    public int id;
    public int version;

    public static readonly Entity Null = new Entity { id = 0, version = 0 };

    public bool IsNull => id == 0;

    public Entity(int id, int version)
    {
        this.id = id;
        this.version = version;
    }

    public bool Equals(Entity other) => id == other.id && version == other.version;
    public override bool Equals(object obj) => obj is Entity other && Equals(other);
    public override int GetHashCode() => id;
    public static bool operator ==(Entity a, Entity b) => a.Equals(b);
    public static bool operator !=(Entity a, Entity b) => !a.Equals(b);
}
```

### 设计要点

**为什么用 struct 而不是 class？** Entity 在游戏里几乎每帧都在创建和传递，struct 是值类型，分配在栈上，不会像 class 那样频繁触发堆分配和 GC。配合 `IEquatable<Entity>` 接口，比较时还能避免装箱，性能优势明显。

**版本号的作用**：`version` 用于防止悬垂引用——如果外部持有已销毁实体的旧 ID，因为 version 对不上，就能检测到实体已失效，避免误操作。实体销毁后，EntityManager 会递增该槽位的版本号，这样后续新实体即使复用了同一个 ID，version 也不同，不会混淆。

**Null 哨兵**：定义了静态只读的 `Entity.Null`，`id=0` 统一作为"空实体"标记，配合 `IsNull` 属性做空值判断。

**运算符重载**：实现了 `==` 和 `!=`，让实体比较像普通值类型一样自然，内部复用 `Equals` 逻辑保证一致性。`GetHashCode` 只基于 `id`，因为同一时刻 ID 唯一。

## ComponentTypes.cs — 组件定义

所有组件都是**纯数据 struct**，按功能分为几个组。每个 struct 只含字段，不包含任何行为逻辑——计算全部交给 System，这也是 ECS 的核心思路。

### 基础组件

```csharp
public struct PositionComponent
{
    public Vector3 value;
}

public struct RotationComponent
{
    public Quaternion value;
}

public struct ScaleComponent
{
    public Vector3 value;
}
```

我把 Transform 拆成了三个独立组件，遵循 ECS "一个组件只做一件事"的原则。好处很明显——如果某个实体不需要旋转或缩放，不挂对应组件即可，节省内存和遍历开销。

### 战斗组件

```csharp
public struct HealthComponent
{
    public float current;
    public float max;
    public bool IsDead => current <= 0f;
}

public struct TeamComponent
{
    public enum TeamType { Player, Enemy, Neutral }
    public TeamType team;
}

public struct DamageComponent
{
    public float value;
    public Entity source;
    public bool isCrit;
}

public struct CollisionComponent
{
    public float radius;
}
```

`HealthComponent` 内置了 `IsDead` 计算属性，避免各个系统到处重复判断 `current <= 0f`。`DamageComponent` 是**瞬态组件**——由伤害系统创建并附加到目标实体，DamageSystem 消费后立即移除。这是 ECS 中处理"一次性事件"的经典模式。`source` 记录了伤害来源实体，方便后续做击杀统计、仇恨系统等功能。

### 运动组件

```csharp
public struct MovementComponent
{
    public Vector3 direction;
    public float speed;
}

public struct TargetComponent
{
    public Entity target;
    public float maxRange;
}
```

Movement 只存方向和速度，由 MovementSystem 每帧读取并更新 Position。分开的好处是——静止的实体无需挂载这个组件，结构更清晰。后续需要加入加速、减速等中间计算时也很方便。

### AI 组件

```csharp
public struct EnemyAIComponent
{
    public AIBehavior behavior;
    public float attackTimer;
    public float attackInterval;
    public float attackRange;
    public float chargeTimer;
    public float chargeDuration;
    public bool isCharging;
    public float stationaryRadius;
}
```

所有 AI 状态集中在一个 struct 中，通过 `AIBehavior` 枚举区分行为类型——追踪、射击、冲锋、瞬移、站桩。`attackTimer` 和 `chargeTimer` 是两个倒计时器，EnemyAISystem 每帧递减，归零时触发对应的攻击或冲锋逻辑。

### 武器/弹幕组件

```csharp
public struct ProjectileComponent
{
    public float damage;
    public float lifetime;
    public int maxPierce;
    public int currentPierce;
    public Entity target;
    public Entity owner;
    public float trackingStrength;
}

public struct OrbitalComponent
{
    public float radius;
    public float angle;
    public float speed;
    public float damage;
    public Entity owner;
}
```

`ProjectileComponent` 支持穿透和追踪——`currentPierce` 记录已穿透次数，与 `maxPierce` 对比判断是否还能继续穿透；`trackingStrength` 控制追踪弧度，设为 0 时直线飞行。`owner` 记录发射者，防止弹幕误伤自身。`OrbitalComponent` 用于火球等环绕物，通过极坐标（半径+角度）描述位置，OrbitalSystem 每帧更新角度即可。

### 生命周期与掉落

```csharp
public struct LifetimeComponent
{
    public float remaining;
}

public struct DropComponent
{
    public int exp;
    public int gold;
}
```

`LifetimeComponent` 逻辑很直接，LifetimeSystem 每帧递减 `remaining`，归零后标记实体待销毁。`DropComponent` 挂在敌人实体上，记录死亡时掉落的经验和金币数量，DeathSystem 读取后生成对应的掉落物实体。

### 标记组件（Tag）

```csharp
public struct DeadTag { }
public struct BossTag { }
public struct ExpOrbTag { }
public struct GoldOrbTag { }
```

标记组件是**零字段 struct**，不包含任何数据，仅用于 ECS 查询时的类型筛选。比如"筛选所有带 BossTag 的实体"、"筛选所有带 ExpOrbTag 的实体做拾取判定"。空 struct 在 ArchetypeChunk 中不占存储空间，属于典型的零成本抽象。

### 桥接组件

```csharp
public struct GameObjectBindingComponent
{
    public GameObject gameObject;
}
```

这是一个桥接组件，连接 ECS 世界与 Unity GameObject 世界。实体需要在场景中有可视化表现时挂载此组件，系统通过它访问 `Transform`、`SpriteRenderer` 等 Unity 原生组件。这种模式保持了 ECS 数据层的纯净，同时不影响与 Unity 引擎的互操作。

---

## 总结

这两个文件构成了项目 ECS 架构的数据基础：`Entity` 解决了实体引用的安全性问题，`ComponentTypes` 用纯数据 struct 实现了数据与逻辑的彻底解耦。后续的 MovementSystem、DamageSystem、EnemyAISystem 等系统，都将基于这套数据结构运行。
