本篇记录两件事：

1. 删除独立的 WeaponBarHUD 面板，武器格子并入 GameHUD，格子用 Bind 的 Element 类型做成组件（WeaponBarSlot），共 9 格
2. 敌人配置从代码硬编码改为 ScriptableObject 资产，绿史莱姆（SlimeGreen）是第一个用资产配置出来的敌人

## 第一件事：武器格子组件化

### 我做了什么

1. 删除 WeaponBarHUD 预制体和它的两个脚本
2. GameHUD 预制体下新增 BarList，里面搭 9 个格子 Slot1~Slot9
3. 每个格子用 Element 类型绑定成 WeaponBarSlot 组件
4. 格子的初始化、高亮、资源条逻辑写进 WeaponBarSlot；武器事件的订阅与分发留在 GameHUD
5. GameRoot 删掉 `OpenPanel<WeaponBarHUD>()`

### Element 使用流程

Bind 组件的"绑定设置"选 Element 时，生成器会为这个控件生成一个独立的 UIElement 子类，面板里的字段类型就是这个类，而不是 Unity 原生组件。完整流程五步：

第一步：搭格子结构。BarList 下放 9 个格子 Slot1~Slot9，每个格子内部三个子控件：Number（编号）、WeaponBarName（武器名）、ResourceBarFill（资源条填充图）。

注意：9 个格子内部子物体的命名必须完全一致。它们共享同一个 WeaponBarSlot 类，名字不一致生成的字段会对不上。

第二步：格子根物体挂 Bind，选 Element。选中 Slot1 根物体 → 挂 Bind → 绑定设置选 **Element** → 类型名填 `WeaponBarSlot`。Slot2~Slot9 同样操作。

第三步：格子内子控件挂 Bind（Default）。选中格子内部的 Number、WeaponBarName、ResourceBarFill，右键 @AddBind，绑定设置保持 Default。

这里有一条关键规则：Element 类型 Bind 的子物体上再挂 Bind，生成代码时子控件字段归属到该元素，而不是面板。框架的搜索逻辑（BindSearchHelper.SearchBinds）遇到非 Default 的 Bind 会以它为父级继续递归，子 Bind 全部收集进这个元素的代码数据里。

第四步：生成代码。选中 GameHUD 预制体 → 生成代码。结果：

- GameHUD.Designer.cs：9 个 `WeaponBarSlot` 类型字段（Slot1~Slot9）
- WeaponBarSlot.Designer.cs：格子内部的 `Number`、`WeaponBarName`、`ResourceBarFill` 三个字段

第五步：写逻辑。WeaponBarSlot 是纯展示组件，不订阅事件，只提供被动接口：

```csharp
public partial class WeaponBarSlot : UIElement
{
    // 初始化编号与武器名
    public void Setup(int slotIndex, string weaponName)
    {
        Number.text = (slotIndex + 1).ToString();
        WeaponBarName.text = weaponName;
    }

    // 切换选中高亮
    public void SetSelected(bool selected)
    {
        mBackground.color = selected ? SelectedColor : NormalColor;
    }

    // 锚点法刷新资源条
    public void SetResource(float current, float max) { ... }
}
```

面板侧统一订阅武器事件，再分发给格子：

```csharp
// GameHUD 的 OnInit 里
mSlots = new[] { Slot1, Slot2, Slot3, Slot4, Slot5, Slot6, Slot7, Slot8, Slot9 };
this.RegisterEvent<WeaponSwitchedEvent>(OnWeaponSwitched)...;

private void OnWeaponSwitched(WeaponSwitchedEvent e)
{
    for (var i = 0; i < mSlots.Length; i++)
    {
        mSlots[i].SetSelected(i == e.SlotIndex);
    }
}
```

最终结构：GameHUD 是唯一的事件订阅者，WeaponBarSlot 只管自己的三个控件和刷新方法。

## 第二件事：敌人配置 ScriptableObject 化

### 我做了什么

1. EnemyConfig 从普通 class 改为 ScriptableObject，加 `[CreateAssetMenu]` 支持右键创建资产
2. 在 `Assets/Resources/Configs/Enemies/` 下创建了绿史莱姆的配置资产 SlimeGreen
3. EnemyConfigTable 从硬编码字典改为懒加载：首次访问时 `Resources.LoadAll<EnemyConfig>("Configs/Enemies")` 填充
4. 刷怪系统的工厂按配置里的 PrefabPath 加载预制体，遍历配置表自动注册所有敌人的对象池

### 配置资产的创建流程

第一步：建文件夹 `Assets/Resources/Configs/Enemies/`。

第二步：右键该文件夹 → Create → Game → 敌人配置，命名为 SlimeGreen。

第三步：选中资产，在 Inspector 填字段：

| 字段 | 值 |
|------|-----|
| Id | slime_green |
| Name | 绿史莱姆 |
| Max HP | 30 |
| Move Speed | 2 |
| Contact Damage | 10 |
| Attack Interval | 1 |
| Attack Range | 1 |
| AI Type | ChaseMelee |
| Exp Value | 1 |
| Prefab Path | Prefabs/GreenSlime |

### 代码侧的加载链路

EnemyConfig 类的核心（字段用 `[SerializeField]` 私有 + 只读属性暴露）：

```csharp
[CreateAssetMenu(fileName = "NewEnemy", menuName = "Game/敌人配置", order = 0)]
public class EnemyConfig : ScriptableObject
{
    [SerializeField] private string mId;          // 敌人唯一 id
    [SerializeField] private int mMaxHP;          // 最大生命
    [SerializeField] private float mMoveSpeed;    // 移动速度
    // ... 其余属性字段
    [SerializeField] private string mPrefabPath;  // 预制体在 Resources 下的路径

    public string Id => mId;
    public string PrefabPath => mPrefabPath;
    // ... 其余只读属性
}
```

EnemyConfigTable 首次访问时加载整个文件夹：

```csharp
private static Dictionary<string, EnemyConfig> LoadAll()
{
    var configs = new Dictionary<string, EnemyConfig>();
    foreach (var config in Resources.LoadAll<EnemyConfig>("Configs/Enemies"))
    {
        configs.Add(config.Id, config);  // id 重复会在这里暴露
    }
    return configs;
}
```

刷怪系统的通用工厂按 id 取配置、按路径加载预制体：

```csharp
private GameObject CreateEnemy(string enemyId)
{
    var config = EnemyConfigTable.Get(enemyId);
    if (!mPrefabCache.TryGetValue(enemyId, out var prefab))
    {
        prefab = Resources.Load<GameObject>(config.PrefabPath);
        mPrefabCache[enemyId] = prefab;
    }
    return Object.Instantiate(prefab);
}
```

PrefabPath 保留字符串寻址而不是直接拖预制体引用，是为后续迁移 Addressables 预留——到时候把值改成 AA 地址、加载层从 Resources.Load 换成 Addressables.LoadAssetAsync，数据资产本身不用动。

新增敌人的成本：在 Configs/Enemies 下再建一个资产填好字段，代码零改动。
