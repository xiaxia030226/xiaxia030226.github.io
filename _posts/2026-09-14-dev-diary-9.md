本篇记录一次 UI 重构：把独立的 WeaponBarHUD 面板拆掉，武器格子合并进 GameHUD，并用 Bind 的 Element 类型把格子做成真正的 UI 组件（WeaponBarSlot）。重点是 Element 类型的用法和适用时机。

## 重构的起因

之前武器格子是独立面板 WeaponBarHUD，问题有两个：一是它和 GameHUD 同属常驻 HUD，分成两个面板没必要；二是格子的编号、武器名、资源条这些子控件全部平铺成面板的字段，格子一多，面板里就是 9 组字段加一堆数组，很乱。

我想要的结构是：格子自己管自己的子控件和刷新方法，面板只持有 9 个格子对象。这就是 Bind 的 Element 类型的用途。

## BindType 三个选项回顾

Bind 组件上的"绑定设置"决定生成代码时字段的类型：

| 选项 | 生成字段类型 | 额外生成脚本 | 适用场景 |
|------|-------------|-------------|---------|
| Default Unity Element | Unity 原生组件（Button/TMP/Image…） | 不生成 | 普通控件，面板直接用 |
| Element | 自定义 UIElement 子类 | 生成到面板专属文件夹 | 控件有自己的逻辑，且只属于这个面板 |
| Component | 自定义 UIElement 子类 | 生成到公共目录 | 控件有自己的逻辑，多个面板复用 |

武器格子只属于 GameHUD，所以选 Element。

## 嵌套 Bind 的归属规则

这次重构的关键机制：Element 类型 Bind 的子物体上再挂 Bind，生成代码时这些子 Bind 的字段会归属到该元素，而不是面板。翻了框架源码（BindSearchHelper.SearchBinds）确认：搜索到非 Default 的 Bind 时会创建 ElementCodeInfo，并以它为父级继续递归子节点，子 Bind 全部收集进这个元素的代码数据里。

所以操作流程是：

1. GameHUD 预制体里搭 9 个格子（Slot1~Slot9），每个格子内部放编号、武器名、资源条三个子控件
2. 给每个格子根物体挂 Bind，绑定设置选 **Element**，自定义类型名填 `WeaponBarSlot`
3. 给每个格子内部的子控件挂 Bind（保持 Default），两个格子间子物体命名必须一致（共享同一个 WeaponBarSlot 类，名字不一致字段会对不上）
4. 选中 GameHUD 预制体生成代码

生成结果：GameHUD.Designer.cs 出现 9 个 `WeaponBarSlot` 类型字段；WeaponBarSlot.Designer.cs 出现格子内部的 `Number`、`WeaponBarName`、`ResourceBarFill` 三个字段。

## 组件的写法

WeaponBarSlot 是纯展示组件：不订阅任何事件，只提供被动接口，由面板调用：

```csharp
public partial class WeaponBarSlot : UIElement
{
    private Image mBackground;  // Awake 里 GetComponent 取格子自身的背景图

    // 初始化编号与武器名
    public void Setup(int slotIndex, string weaponName)
    {
        Number.text = (slotIndex + 1).ToString();
        WeaponBarName.text = weaponName;
    }

    // 切换选中高亮
    public void SetSelected(bool selected)
    {
        mBackground.color = selected ? SelectedColor : NormalColor;
    }

    // 锚点法刷新资源条
    public void SetResource(float current, float max) { ... }
}
```

面板侧统一订阅事件再分发：

```csharp
// GameHUD 的 OnInit 里
mSlots = new[] { Slot1, Slot2, ..., Slot9 };
this.RegisterEvent<WeaponSwitchedEvent>(OnWeaponSwitched)...;

private void OnWeaponSwitched(WeaponSwitchedEvent e)
{
    for (var i = 0; i < mSlots.Length; i++)
    {
        mSlots[i].SetSelected(i == e.SlotIndex);
    }
}
```

## 重构后的分层

```
GameHUD（面板）            ← 唯一的事件订阅者，收 WeaponSwitchedEvent / WeaponResourceChangedEvent
    └─ WeaponBarSlot × 9（元素）  ← 纯展示，只提供 Setup/SetSelected/SetResource
```

格子不知道事件的存在，面板不知道格子内部有什么控件。扩展格子数量只需要在预制体里加一格绑定、数组里加一项，逻辑零改动。

## 什么时候该用 Element

这次重构让我对 Element 的适用时机有了具体判断标准：

- 一组控件**重复出现**（9 个相同的格子）——平铺字段会让面板字段数爆炸
- 这组控件**有自己的行为**（高亮、资源条刷新）——行为收进组件，面板不用管细节
- 只属于一个面板就用 Element；要跨面板复用（比如通用血条）就用 Component

反过来说，只出现一次、没有独立行为的控件（标题文字、单个按钮），继续用 Default 就好，不需要为了组件化而组件化。
