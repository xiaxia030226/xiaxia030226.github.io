游戏运行时经常需要频繁创建和销毁对象（比如子弹、特效、敌人），直接 `new` + 销毁会产生大量 GC，导致卡顿。对象池的核心思想是**复用对象**，用完后回收而不是销毁，下次需要时从池中取出即可。

## 文件结构

```
Assets/Scripts/GameFrameWork/Pool/
├── IPool.cs            # 池接口
├── IPoolObj.cs         # 池对象接口
├── ObjectPool.cs       # 全局对象池（单例，管理所有子池）
└── SubObjectPool.cs    # 子对象池（管理同类型对象，使用 Stack）
```

---

## 1. `IPool.cs` —— 池接口

```csharp
public interface IPool
{
    IPoolObj GetObject();
    void PutObject(IPoolObj obj);
}
```

所有池共有的接口，定义了取出和放入两个基本操作。

---

## 2. `IPoolObj.cs` —— 池对象接口

```csharp
public interface IPoolObj
{
    void FirstInit();
    void ResetData();
}
```

任何需要进入对象池的对象都必须实现此接口：

- `FirstInit()`：对象首次创建时调用，做一次性初始化（如获取组件引用）。
- `ResetData()`：每次取出或放回前调用，重置状态数据（如归零坐标、清空引用）。

---

## 3. `ObjectPool.cs` —— 全局对象池

```csharp
using System;
using System.Collections.Generic;

public class ObjectPool : Singleton<ObjectPool>
{
    public readonly Dictionary<Type, IPool> pools = new Dictionary<Type, IPool>();

    public IPoolObj GetObject<T>() where T : IPoolObj, new()
    {
        Type type = typeof(T);

        if (pools.TryGetValue(type, out IPool pool))
        {
            return pool.GetObject();
        }
        else
        {
            IPool newPool = new SubObjectPool<T>();
            pools[type] = newPool;
            return newPool.GetObject();
        }
    }

    public void PutObject(IPoolObj obj)
    {
        Type type = obj.GetType();
        if (pools.TryGetValue(type, out IPool pool))
        {
            pool.PutObject(obj);
        }
    }
}
```

全局对象池继承自上一篇的 `Singleton<ObjectPool>`，通过 `Dictionary<Type, IPool>` 管理每种类型对应的子池。首次获取某类型对象时自动创建对应的 `SubObjectPool<T>`。

## 4. `SubObjectPool.cs` —— 子对象池

```csharp
using System.Collections.Generic;

public class SubObjectPool<T> : IPool where T : IPoolObj, new()
{
    public readonly Stack<IPoolObj> objects = new Stack<IPoolObj>();

    public IPoolObj GetObject()
    {
        if (objects.Count > 0)
        {
            IPoolObj obj = objects.Pop();
            obj.ResetData();
            return obj;
        }
        else
        {
            IPoolObj obj = new T();
            obj.FirstInit();
            obj.ResetData();
            return obj;
        }
    }

    public void PutObject(IPoolObj obj)
    {
        if (obj is not T) return;
        obj.ResetData();
        objects.Push(obj);
    }
}
```

内部使用 **`Stack<IPoolObj>`** 存储空闲对象：取出用 `Pop`，放回用 `Push`。池中没有空闲对象时才 `new T()` 创建新实例。

---

## 编写中遇到的问题

### 问题一：泛型约束

`ObjectPool` 的 `GetObject<T>` 方法签名是 `where T : IPoolObj, new()`，这意味着类型 `T` 必须同时实现 `IPoolObj` 接口且有无参构造函数。同样的约束也出现在 `SubObjectPool<T>` 上。

起初尝试只写 `where T : IPoolObj`，但内部 `new T()` 会报编译错误——不是所有类都有无参构造函数。加上 `new()` 约束后，编译器才能保证 `new T()` 是合法的。

### 问题二：为什么子池用 `Stack` 而不是 `List`

第一版用的是 `List<IPoolObj>`，取对象时取 `List[0]` 然后 `RemoveAt(0)`。这有两个问题：

1. **性能差**：`RemoveAt(0)` 会导致后续所有元素向前移动一位，时间复杂度 O(n)。
2. **语义不对**：对象池是"后进先出"的场景——最后放回的对象在内存中还是"热"的，优先复用它更利于缓存局部性。

改用 `Stack` 后：

- `Pop()` 和 `Push()` 都是 O(1) 操作，性能更好。
- 后进先出的语义天然吻合对象池的使用场景。
