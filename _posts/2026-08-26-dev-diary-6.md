项目使用 Unity 新输入系统（Input System）管理玩家输入。相比传统的 `Input.GetKeyDown(KeyCode.Space)` 写法，新输入系统将“动作”和“具体按键”分离，代码只关心动作是否发生，按键绑定则集中在输入初始化代码中维护。

## 创建 InputAction

可以通过静态类统一管理项目中的输入动作：

```csharp
public static class GameInput
{
    public static InputAction Move { get; private set; }
    public static InputAction MousePosition { get; private set; }
    public static InputAction Attack { get; private set; }
    public static InputAction Skill1 { get; private set; }

    public static void Init()
    {
        Move = new InputAction("Move", InputActionType.Value, expectedControlType: "Vector2");
        Move.AddCompositeBinding("2DVector")
            .With("Up", "<Keyboard>/w")
            .With("Down", "<Keyboard>/s")
            .With("Left", "<Keyboard>/a")
            .With("Right", "<Keyboard>/d");

        MousePosition = new InputAction(
            "MousePosition",
            InputActionType.Value,
            "<Mouse>/position",
            expectedControlType: "Vector2");

        Attack = new InputAction(
            "Attack",
            InputActionType.Button,
            "<Mouse>/leftButton");

        Skill1 = new InputAction(
            "Skill1",
            InputActionType.Button,
            "<Keyboard>/space");
    }
}
```

### 移动输入

`Move` 使用 `InputActionType.Value`，因为它代表一个持续变化的二维向量。通过 `AddCompositeBinding("2DVector")` 将 W、A、S、D 四个按键组合成一个 `Vector2` 输入。

### 鼠标位置

`MousePosition` 同样属于值类型输入，绑定到 `<Mouse>/position`，可以读取当前鼠标在屏幕上的位置。

### 按钮输入

`Attack` 和 `Skill1` 使用 `InputActionType.Button`，分别绑定鼠标左键和键盘空格键。这类输入适合表示攻击、跳跃、技能等一次性操作。

## 使用 InputAction

输入动作创建后，可以通过动作提供的状态方法判断它是否在当前帧被触发：

```csharp
if (GameInput.Skill1.WasPressedThisFrame())
{
    // 释放技能
}
```

以 `Attack` 为例：`Attack` 是动作名称，`InputActionType.Button` 是动作类型，`<Mouse>/leftButton` 表示该动作由鼠标设备的左键触发。其中 `<Mouse>` 表示输入设备，`leftButton` 表示设备上的具体控制项。

代码判断的是“攻击动作是否被按下”，而不是“鼠标左键是否被按下”。如果之后需要把攻击键改成键盘按键，只需要修改初始化时的绑定，不需要修改业务逻辑。

## 与传统输入写法的区别

传统写法通常会把输入设备、具体按键和业务判断写在一起：

```csharp
if (Input.GetKeyDown(KeyCode.Space))
{
    // 释放技能
}
```

这种方式直接将技能绑定到空格键。使用 `InputAction` 后，业务代码只依赖 `Skill1` 这个动作，按键绑定集中在 `GameInput.Init()` 中，输入配置和游戏逻辑得到了分离。

| 对比项 | 传统输入 | 新输入系统 |
| --- | --- | --- |
| 业务代码依赖 | 具体按键 | 输入动作 |
| 修改按键 | 修改业务判断代码 | 修改绑定配置 |
| 多设备支持 | 需要额外处理 | 可以为动作配置多个绑定 |
| 输入类型 | 由 API 固定 | 可以声明 Button、Value 等类型 |

## 编写中需要注意的问题

`InputAction` 创建出来后默认处于未启用状态。初始化完成后，必须调用 `Enable()`，否则动作不会接收输入：

```csharp
GameInput.Init();
GameInput.Move.Enable();
GameInput.MousePosition.Enable();
GameInput.Attack.Enable();
GameInput.Skill1.Enable();
```

不再使用时，可以调用 `Disable()`，并在合适的生命周期中释放相关对象。实际项目中还需要确保初始化和启用顺序早于各个角色、UI 或控制器读取输入的时机。

## 小结

Unity 新输入系统的核心是把输入动作抽象出来：`InputAction` 描述玩家想做什么，Binding 描述玩家通过什么设备和按键完成这个动作。这样既能减少输入判断与具体按键之间的耦合，也为后续支持手柄、不同键位配置和多平台输入提供了更好的扩展基础。
